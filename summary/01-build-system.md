# Build system & dependency management - analysis

## Purpose

This subsystem turns a Qt6/Boost/ms-gsl C++17 source tree into two build
artifacts from a single source set - the desktop application executable
`qt6-template` and a static library `qt6-template_LIB` - and manages how the
third-party dependencies are fetched (Conan) and resolved (CMake `find_package`).
The two-target split exists so the test suite can link the compiled application
code as a library without pulling in `main()`, keeping tests independent of the
GUI entrypoint. The subsystem also provides the developer ergonomics layer
(`Makefile`, `CMakePresets.json`), the lint/format configuration
(`.clang-format`, `.clang-tidy`), and the desktop/icon packaging inputs.

## Architecture & responsibilities

The build is layered. Conan sits underneath CMake; CMake is driven either by the
`Makefile`, by `CMakePresets.json`, or directly (as CI does). The root
`CMakeLists.txt` is the orchestrator; the `cmake/*.cmake` files are included
helpers that either declare data (`Modules.cmake`, `Sources.cmake`,
`Resources.cmake`) or apply policy (`StandardSettings.cmake`,
`CompilerWarnings.cmake`).

```
 developer / CI
      |
      |  make <target> | cmake --preset | raw cmake
      v
 +----------------------- Makefile (thin wrapper) ------------------------+
 |  conan -> configure -> build -> run/test/docs/format/tidy/clean        |
 +------------------------------------------------------------------------+
      |                                   |
      | conan install                     | cmake -DCMAKE_TOOLCHAIN_FILE=
      v                                   v
 conan/conanfile.txt  --generates-->  conan/conan_toolchain.cmake + CMakeDeps/*.cmake
 (boost, ms-gsl)                          (gitignored, machine-local)
                                          |
                                          v
                          +----------------- CMakeLists.txt ----------------+
                          | include Modules.cmake  (dep lists)              |
                          | find_package loops: Sys/MODULES/Boost/GSL/Qt6   |
                          | C++17 + AUTOMOC/UIC/RCC + qt6_standard_setup     |
                          | include StandardSettings.cmake (options+flags)  |
                          | include Sources.cmake  (SOURCE_FILES glob)      |
                          |                                                 |
                          |  if BUILD_EXECUTABLE:                           |
                          |    qt_add_executable(qt6-template   SOURCE_FILES)|
                          |    qt_add_library  (qt6-template_LIB SOURCE_FILES)| <- SAME sources
                          |  else: qt_add_library(qt6-template STATIC ...)  |
                          |                                                 |
                          | set_project_warnings(qt6-template)  (exe+lib)  |
                          | target_link_libraries: MODULES/Qt6::*/Boost::*/ |
                          |                        Microsoft.GSL::GSL       |
                          | Resources.cmake -> qt_add_resources/qml_module  |
                          | install + qt_generate_deploy_script             |
                          | add_subdirectory(test)  --> testing domain      |
                          +-------------------------------------------------+
```

Responsibility split:

- **Dependency declaration**: `cmake/Modules.cmake` is the single source of truth
  for which libraries exist. Adding a Qt module or Boost component is a one-line
  edit there; the `find_package` and `target_link_libraries` loops pick it up.
- **Dependency provisioning**: `conan/conanfile.txt` + the `conanLibrariesInstall`
  scripts provision Boost and ms-gsl into `~/.conan2`. Qt6 is **not** provisioned
  by Conan - it is resolved from the system / an externally installed Qt (CI uses
  `jurplel/install-qt-action` at Qt `6.11.*`).
- **Target definition**: root `CMakeLists.txt` `:86-116`.
- **Build policy**: `cmake/StandardSettings.cmake` (options + sanitizer flags) and
  `cmake/CompilerWarnings.cmake` (warning flags).
- **Resource packaging**: `cmake/Resources.cmake` + `CMakeLists.txt:185-199`.
- **Developer UX**: `Makefile`, `CMakePresets.json`.

## Data structures & models

The "data structures" here are CMake list variables and Conan manifests.

Dependency lists (`cmake/Modules.cmake:1-7`):

```cmake
set(SYS_MODULES)                       # system find_package(REQUIRED), module mode - currently EMPTY
set(MODULES)                           # CONFIG-mode packages - currently EMPTY
set(BOOST_COMPONENTS filesystem)       # Boost:: components
set(QT_COMPONENTS Core Gui Widgets)    # Qt6:: components
```

Source lists (`cmake/Sources.cmake:1-7`):

```cmake
file(GLOB_RECURSE SOURCE_FILES src/*.cpp src/*.h src/*.ui)   # feeds BOTH exe and lib
file(GLOB_RECURSE TEST_FILES  test/*.cpp)                    # feeds test/CMakeLists.txt
```

Resource lists (`cmake/Resources.cmake:1-19`):

```cmake
file(GLOB_RECURSE QML_FILES src/qml/*.qml)   # each gets QT_RESOURCE_ALIAS = path relative to src/qml
set(RESOURCES icon/icon_32x32.png icon/icon_64x64.png)
# TEST_RESOURCES = each RESOURCES entry with "../" prepended (test dir is one level down)
```

Conan manifest (`conan/conanfile.txt`):

```
[requires]
boost/1.91.0
ms-gsl/4.2.2
[generators]
CMakeDeps        # generates <Pkg>Config.cmake + imported targets
CMakeToolchain   # generates conan_toolchain.cmake
```

Build options (all prefixed `qt6-template_`, `cmake/StandardSettings.cmake`):

| Option | Default | Effect | Line |
| --- | --- | --- | --- |
| `qt6-template_BUILD_EXECUTABLE` | ON | Build exe **and** `_LIB`; OFF builds one static lib | `:5` |
| `qt6-template_USE_ALT_NAMES` | ON | Lower/upper-case project name aliases | `:6` |
| `qt6-template_WARNINGS_AS_ERRORS` | OFF | Adds `-Werror` / `/WX` | `:12` |
| `qt6-template_ENABLE_LTO` | ON | `CMAKE_INTERPROCEDURAL_OPTIMIZATION TRUE` (after `check_ipo_supported`) | `:28-37` |
| `qt6-template_ENABLE_ASAN` | OFF | `-fsanitize=address` compile + link | `:39-43` |
| `qt6-template_ENABLE_UBSAN` | OFF | `-fsanitize=undefined` compile + link | `:45-49` |
| `qt6-template_ENABLE_COVERAGE` | OFF | `--coverage -O0 -g` compile, `--coverage` link | `:51-55` |

The Conan toolchain (`conan/conan_toolchain.cmake`, generated) pins
`CMAKE_CXX_STANDARD 17`, `CMAKE_CXX_EXTENSIONS ON` (`:62-63`), injects `-m64`
(`:30-34`), sets `CMAKE_FIND_PACKAGE_PREFER_CONFIG ON` (`:142`), and **prepends
absolute machine-local paths** into `CMAKE_LIBRARY_PATH` / `CMAKE_INCLUDE_PATH`
pointing at `/home/kyenero/.conan2/p/...` (`:151-153`). Those paths are why the
file is gitignored and must be regenerated per machine.

## Control & data flow

Primary path (a clean `make build` / `make test`, i.e. the documented dev loop):

1. **Provision** - `make conan` (`Makefile:16-18`) runs
   `conan install conan/ --build=missing --settings=build_type=Debug` then the
   same for `Release`. Conan reads `conan/conanfile.txt`, resolves `boost/1.91.0`
   + `ms-gsl/4.2.2` (plus transitive `zlib`, `bzip2`, `libbacktrace`), builds
   missing binaries, and writes `conan_toolchain.cmake` + `CMakeDeps` config files
   into `conan/`. First-time bootstrap is `bash conanLibrariesInstall.sh` (creates
   `.venv`, `pip install conan`, `conan profile detect`, then the two installs).
2. **Configure** - `make configure` (`Makefile:20-21`) runs
   `cmake . -G Ninja -B build -DCMAKE_TOOLCHAIN_FILE=conan/conan_toolchain.cmake -DCMAKE_BUILD_TYPE=Release`.
   CMake loads the Conan toolchain first, then executes `CMakeLists.txt`:
   - `:8-9` map `RelWithDebInfo`/`MinSizeRel` imported configs onto `Release`
     (Conan only generates Debug/Release imported targets).
   - `:18-25` `include(cmake/Modules.cmake)`; loop `find_package(${sys_library} REQUIRED)`
     over `SYS_MODULES` (empty), then `find_package(${library} CONFIG REQUIRED)` over
     `MODULES` (empty).
   - `:27-32` set `Boost_USE_STATIC_LIBS OFF`, `Boost_USE_MULTITHREADED ON`,
     `Boost_USE_STATIC_RUNTIME OFF`; loop `find_package(Boost CONFIG COMPONENTS ${boost_component} REQUIRED)`
     over `BOOST_COMPONENTS` (`filesystem`). Resolved via `conan/BoostConfig.cmake`.
   - `:34` `find_package(Microsoft.GSL CONFIG REQUIRED)` - resolved via
     `conan/Microsoft.GSLConfig.cmake`, header-only, single imported target
     `Microsoft.GSL::GSL`.
   - `:39-45` loop `find_package(Qt6 COMPONENTS ${library} REQUIRED)` over
     `QT_COMPONENTS` (`Core Gui Widgets`). If any component lower-cases to `quick`,
     set `${PROJECT_NAME}_QT_QUICK ON` (currently never - no Quick component).
   - `:48-57` C++17 required, `AUTOMOC/AUTOUIC/AUTORCC ON`,
     `qt6_standard_project_setup()`, MSVC runtime library.
   - `:59` `include(cmake/StandardSettings.cmake)` - defines options and, when a
     sanitizer/coverage option is ON, calls `add_compile_options` /
     `add_link_options` at directory scope (so they apply to **every** target
     created afterward, including the test targets via the later `add_subdirectory`).
     `_ENABLE_LTO` runs `check_ipo_supported` and sets
     `CMAKE_INTERPROCEDURAL_OPTIMIZATION TRUE`.
   - `:60-66` default `CMAKE_BUILD_TYPE Debug` if unset; on UNIX, add `-D_DEBUG`
     for Debug configs.
   - `:78-80` fatal-error guard against in-source builds.
   - `:83` `include(cmake/Sources.cmake)` -> populates `SOURCE_FILES`.
   - `:86-116` **the two-target block** (see next step).
   - `:127-131` `include(cmake/CompilerWarnings.cmake)` +
     `set_project_warnings` on the executable AND (guarded by `BUILD_EXECUTABLE`)
     the static library; every test target gets the same call in
     `test/CMakeLists.txt:25`.
   - `:133-163` include directories, link directories, and the single shared
     `project_link_dependencies` link recipe.
   - `:185-199` include `cmake/Resources.cmake`; `qt_add_qml_module` if
     `_QT_QUICK` else `qt_add_resources(${PROJECT_NAME} "resources" PREFIX "/resource" FILES ${RESOURCES})`.
   - `:267-307` platform install rules + `qt_generate_deploy_script`.
   - `:309-311` `enable_testing(true)` + `add_subdirectory(test)`.
3. **Two-target creation** (`CMakeLists.txt:86-116`, the load-bearing branch):
   - With `qt6-template_BUILD_EXECUTABLE=ON` (default):
     - `qt_add_executable(qt6-template <MACOSX_BUNDLE|WIN32> ${SOURCE_FILES} [icon])`
       chooses `icon/icon.icns` on APPLE, `icon/icon.rc` on WIN32, none on Linux.
     - `qt_add_library(qt6-template_LIB STATIC ${SOURCE_FILES})` - **the identical
       `SOURCE_FILES` list**, so every `src/*.cpp` is compiled twice (once for the
       exe, once for the lib). The lib gets `OUTPUT_NAME qt6-template` and archives
       to `build/lib/${CMAKE_BUILD_TYPE}/libqt6-template.a`.
     - Both get `target_compile_features(... PUBLIC cxx_std_17)`.
   - With `qt6-template_BUILD_EXECUTABLE=OFF`: a single
     `qt_add_library(qt6-template STATIC ${SOURCE_FILES})` and the aliased target is
     the library.
4. **Link** (`CMakeLists.txt:159-163`) - call the shared `project_link_dependencies`
   helper (defined once at the END of `cmake/Modules.cmake`) on the exe and
   (guarded by `BUILD_EXECUTABLE`) on `_LIB`. The helper loops `MODULES`,
   `QT_COMPONENTS` (`Qt6::Core/Gui/Widgets`), `BOOST_COMPONENTS`
   (`Boost::filesystem`), and links `Microsoft.GSL::GSL`, all `PRIVATE`. It is the
   only link recipe - the test targets consume the same helper (no duplicated
   per-component loops remain).
5. **Build** - `make build` (`Makefile:23-24`, depends on `configure`) runs
   `cmake --build build --config Release -j4`. Ninja compiles the two targets and
   the four test executables.
6. **Test** - `make test` (`Makefile:29-30`) runs
   `cd build && QT_QPA_PLATFORM=offscreen ctest -C Release -VV`. Each `test/*.cpp`
   became a `<name>_Tests` executable linking `qt6-template_LIB` (see testing
   domain).

Important branches:

- **Qt Quick vs Widgets resources**: `_QT_QUICK` is OFF (no `Quick` component), so
  `qt_add_resources` (the `.qrc` path) runs, not `qt_add_qml_module`. The
  `src/qml/` directory holds only a placeholder file.
- **Platform icon branches** (`:87-104`, `:268-279`) diverge by APPLE / WIN32 /
  other for icon embedding and bundle/executable flags.
- **Sanitizer/coverage branches** in `StandardSettings.cmake` are directory-scoped
  and reach the test targets because they run before `add_subdirectory(test)`.

## Public API / contracts

Downstream consumers (tests, CI, docs, other domains) may rely on:

- **CMake targets**:
  - `qt6-template` - the executable (aliased `qt6-template::qt6-template`,
    `CMakeLists.txt:262`).
  - `qt6-template_LIB` - the static library holding the app code; the **contract
    the test domain depends on** (test/CMakeLists.txt links
    `${CMAKE_PROJECT_NAME}_LIB`). Output `build/lib/<config>/libqt6-template.a`.
  - `<name>_Tests` targets + CTest tests `errorHandlingTest`, `gslLinkTest`,
    `integrationSmokeTest`, `testTest` (defined in the test domain but registered via
    `enable_testing` here).
- **CMake variables exported for the test subdir**: `SOURCE_FILES`, `TEST_FILES`,
  `MODULES`, `QT_COMPONENTS`, `BOOST_COMPONENTS`, `QML_FILES`, `TEST_RESOURCES`,
  `QML_URI`, `${PROJECT_NAME}_BUILD_EXECUTABLE`, `${PROJECT_NAME}_QT_QUICK`,
  `CMAKE_CXX_STANDARD`.
- **Build options** (stable names, `-D<name>=ON` at configure time):
  `qt6-template_ENABLE_ASAN`, `_ENABLE_UBSAN`, `_ENABLE_COVERAGE`, `_ENABLE_LTO`,
  `_WARNINGS_AS_ERRORS`, `_BUILD_EXECUTABLE`, `_USE_ALT_NAMES`.
- **Presets**: configure `ninja-release` / `ninja-debug`, build `release` / `debug`,
  test `release`. `ninja-release` binaryDir is `build/`; `ninja-debug` is
  `build-debug/`.
- **Makefile targets** (frozen 12): `help conan configure build run test docs
  docs-serve docs-clean format tidy clean`. Overridable variables: `BUILD_DIR`
  (`build`), `BUILD_TYPE` (`Release`), `TOOLCHAIN`
  (`conan/conan_toolchain.cmake`), `GENERATOR` (`Ninja`), `JOBS` (`4`), `QPA`
  (`offscreen`).
- **Conan contract**: `conan/conanfile.txt` requires `boost/1.91.0`,

- **Lint contract**: `.clang-format` (Microsoft base, C++17, 4-space, 100 col,

  `modernize-*`/`readability-*`, `HeaderFilterRegex '^src/'`,
  `WarningsAsErrors ''`).

Guarantees: C++17 is enforced globally; both exe and lib compile the same sources
under the same standard; the static lib is what tests link; the offscreen QPA env
is what makes tests headless.

## Invariants & assumptions

- **Both targets share exactly one source list.** `SOURCE_FILES`
  (`Sources.cmake:1-4`) feeds both `qt_add_executable` and
  `qt_add_library(_LIB)`. If they ever diverge, tests would link code that is not
  in the shipped executable.
- **`Modules.cmake` is the dependency single-source-of-truth.** The
  `find_package` loops and the `target_link_libraries` loops iterate the same
  lists; a library added to a list but missing from the other loop, or vice versa,
  breaks resolution/linking.
- **Conan must run before CMake configure.** `conan/conan_toolchain.cmake` and the
  `CMakeDeps` files must exist or `find_package(Boost/Microsoft.GSL CONFIG REQUIRED)`
  fails. `make configure` does not depend on `make conan`, but it now guards the
  toolchain: a missing `conan/conan_toolchain.cmake` fails fast with
  `error: conan toolchain not found at ...; run 'make conan' first` before CMake runs
  (`Makefile:21`).
- **Qt6 is provided out-of-band.** Nothing in this subsystem installs Qt; it must
  be discoverable by `find_package(Qt6)` (system path or `CMAKE_PREFIX_PATH`).
- **Out-of-source builds only** (`CMakeLists.txt:78-80` fatal-errors otherwise).
- **C++17 exactly** - `CMAKE_CXX_STANDARD 17` + `STANDARD_REQUIRED ON`; the Conan
  toolchain additionally forces `CMAKE_CXX_EXTENSIONS ON`.
- **Config mapping**: RelWithDebInfo / MinSizeRel rely on the imported-config
  remap (`:8-9`); removing it breaks those configs against Conan targets.
- **`ErrorTypeStr[]` sync** and other src invariants are the app domain's, not this
  one's.

## Error handling & edge cases

- **Missing dependency**: every `find_package` is `REQUIRED`, so a missing Boost /
  ms-gsl / Qt6 component halts configure with a hard error. Same for
  `find_package(Qt6 COMPONENTS Test)` in the test subdir.
- **In-source build**: explicit `message(FATAL_ERROR ...)` (`:78-80`).
- **LTO unsupported**: `check_ipo_supported` -> `message(SEND_ERROR ...)`
  (`StandardSettings.cmake:35`). `SEND_ERROR` (not `FATAL_ERROR`) means configure
  continues but generation fails - a partially confusing failure mode on toolchains
  without IPO. Workaround: `-Dqt6-template_ENABLE_LTO=OFF`.
- **Conan generates only Debug/Release imported targets**: handled by the config
  remap (`:8-9`) and by the commented-out `CMP0111` policy notes (`:11-14`,
  `:36-37`) that acknowledge Ninja single-config warnings about missing imported
  locations for the other configs (intentionally left noisy, not silenced).
- **install-qt-action version drift**: `ubuntu-debug.yml:42` explicitly notes
  "fall back to '6.8.*' if it does not" resolve - an anticipated edge case for
  when `6.11.*` is not yet published by aqt.
- **Bootstrap script failures**: `conanLibrariesInstall.ps1` guards each step
  (`python`, `pip`, `conan` presence) with `Write-Error` + `exit 1`; the `.sh`
  variant has no such guards and relies on the shell continuing.
- **`compile_commands.json`** is always emitted (`StandardSettings.cmake:19`) so
  `make tidy` has a compilation database in `build/`.

## Concurrency / async / lifecycle

Build-time only; no runtime concurrency in this subsystem. Parallelism is
build-job parallelism: `make build` passes `-j4`, root presets do not set jobs,
the generated `conan/CMakePresets.json` hardcodes `jobs: 24`. Lifecycle ordering
that matters: `conan install` (produces toolchain) -> `cmake configure` -> `cmake
build` -> `ctest`. The `Makefile` chains `run`/`test` -> `build` -> `configure`
via prerequisites, but deliberately does **not** chain `configure` -> `conan`. A
first-time user who skips `make conan` now hits the `configure` recipe's toolchain
guard (`Makefile:21`), which exits non-zero with an actionable `run 'make conan'
first` message before CMake runs - no longer a raw `find_package` failure.

## Performance

- **Doubled compilation**: because the exe and `_LIB` are built from the same
  `SOURCE_FILES`, every translation unit is compiled twice. For a template with a
  handful of files this is negligible, but it scales linearly with source count and
  is the main build-time cost multiplier.
- **LTO on by default** (`_ENABLE_LTO ON`) increases link time for release-style
  builds; it is global (`CMAKE_INTERPROCEDURAL_OPTIMIZATION`) so it also affects
  the lib and tests.
- **Conan caching**: CI caches `~/.conan2` keyed on `hashFiles('conan/conanfile.txt')`
  (e.g. `ubuntu.yml:62-68`), and `--build=missing` avoids rebuilding cached
  binaries. Qt is cached via the install-qt-action cache.
- No runtime hot paths owned here.

## Gotchas & footguns

- **Project warnings apply to every target.** `set_project_warnings` is called on
  the exe and `qt6-template_LIB` (`CMakeLists.txt:128-131`) and on every
  `<name>_Tests` target (`test/CMakeLists.txt:25`), attaching options `PUBLIC`. The
  exe, the static lib compiled from the identical sources, and the test binaries all
  carry `-Wall -Wextra ...` (so a `-Dqt6-template_WARNINGS_AS_ERRORS=ON` build must
  be clean across all of them).
- **`_WARNINGS_AS_ERRORS` reads a global, not the argument**: `CompilerWarnings.cmake:64`
  checks `${CMAKE_PROJECT_NAME}_WARNINGS_AS_ERRORS` (a global) rather than the function
  argument `${project_name}` - which is what lets the `-Werror`/`/WX` flag apply
  consistently now that the function is called for the exe, the lib, and every test
  target. The never-defined `${PROJECT_NAME}_BUILD_HEADERS_ONLY` (`:90`) always
  evaluates false, so the `INTERFACE` branch is dead.
- **Two different default build types.** The `Makefile` defaults `BUILD_TYPE=Release`
  and passes `-DCMAKE_BUILD_TYPE=Release`, but raw `cmake` with no build type falls
  back to `Debug` (`CMakeLists.txt:60-62`). `make run`/`make test` therefore exercise
  Release, whereas a hand-run `cmake` may silently build Debug.
- **`conan/CMakePresets.json` carries a hardcoded absolute `binaryDir`** of
  `/home/kyenero/lighttab2/qt6-template/conan` and `jobs: 24`. The root
  `CMakePresets.json` `include`s it, so its `conan-release` preset is exposed but is
  machine-specific and would configure into `conan/` with Unix Makefiles - do not use
  it; use `ninja-release`/`ninja-debug`.
- **The entire `conan/` tree except `conanfile.txt` is generated and gitignored**
  (`.gitignore:2-3`). The `conan_toolchain.cmake` bakes in absolute
  `/home/kyenero/.conan2/...` include/lib paths (`:151-153`); it is per-machine and
  must be regenerated with `make conan` / `conanLibrariesInstall.*`. Do not commit
  or hand-edit it.
- **`make clean` deletes directories no target creates**: `build-rwdi build-ubsan
  build-cov` (`Makefile:48`) are aspirational (only `build` and preset `build-debug`
  are ever created). Harmless but misleading.
- **`make format`'s find lacks parentheses**:
  `find src test -name '*.cpp' -o -name '*.h'` (`Makefile:42`). The implicit action
  binds to the whole OR so it does format both extensions, but it is fragile - adding
  an explicit `-print`/action would break it. Easy to "fix" wrong.
- **`make tidy` runs clang-tidy only over `src/*.cpp`** (`Makefile:45`), not headers
  or tests, and needs a configured `build/` for the compile DB. `HeaderFilterRegex '^src/'`
  in `.clang-tidy` still gates header diagnostics.
- **`include/` does not exist.** Both the exe/lib and test targets add
  `$<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>` (`CMakeLists.txt:134`,
  `:147`; `test/CMakeLists.txt:26`) but there is no `include/` directory - dead
  template scaffolding; real headers live in `src/` (added `PRIVATE`).
- **`Microsoft.GSL::GSL` is linked separately, not through a list** - it is a
  dedicated line at the end of `project_link_dependencies` (`cmake/Modules.cmake:21`),
  not a `*_COMPONENTS` loop; adding another header-only lib means editing that helper.
- **QML/`_QT_QUICK` path is latent**: `src/qml/` holds only a placeholder
  ("Here you should place your qml files"). Adding a `Quick` component to
  `QT_COMPONENTS` flips `_QT_QUICK ON` and silently swaps `qt_add_resources` for
  `qt_add_qml_module` (`:188-199`), changing the resource model.

Known dead ends (from git history / `plan/dead-ends.md` at HEAD): the plan's
dead-ends ledger is effectively empty ("cavemem recall returned none; filled as
leads report") - no abandoned build approaches were recorded. Git log shows the
build modernization landed cleanly in `ba18609`
("feat(build): bump deps, wire ms-gsl, add sanitizers/presets/lint"); the only
policy notes intentionally left in place are the commented-out `CMP0111`
toggles (`CMakeLists.txt:11-14`, `:36-37`), kept as documentation of the
Ninja/Conan single-config warning rather than silencing it.

## Tech debt & smells

- `CMakeLists.txt:106` - `_LIB` recompiles the same `SOURCE_FILES` as the exe;
  doubled build cost and the warnings asymmetry above. A cleaner design compiles an
  OBJECT library once and reuses the objects.
- `cmake/CompilerWarnings.cmake:64,90` - the `WARNINGS_AS_ERRORS` check reads the
  global `${CMAKE_PROJECT_NAME}_...` rather than the function argument
  `${project_name}_...`, plus a permanently-dead `_BUILD_HEADERS_ONLY` branch.
- `Makefile:48` - `clean` removes nonexistent `build-rwdi/build-ubsan/build-cov`.
- `Makefile:42` - `format` find without parentheses (fragile).
- `conan/CMakePresets.json:22,29,38` - absolute `binaryDir` and hardcoded `jobs: 24`
  in a generated file that the root preset includes.
- `CMakeLists.txt:134,147` / `test/CMakeLists.txt:26` - reference a nonexistent
  `include/` dir.
- `conanLibrariesInstall.sh` - no error handling / no `set -e`, unlike the guarded
  `.ps1` counterpart.
- `CMakeLists.txt:200-256` - a very long, hand-maintained `source_group` block that
  hardcodes per-config autogen paths (`include_Debug`, `include_Release`, ...); IDE
  cosmetics that will silently drift if Qt changes its autogen layout.

## Test surface

This subsystem is exercised indirectly - the tests are defined by the testing
domain but registered here via `enable_testing(true)` +
`add_subdirectory(test)` (`CMakeLists.txt:309-311`). Framework: **Qt Test**
(`QTEST_MAIN`), one executable per `test/*.cpp`, discovered by the `TEST_FILES`
glob and run through CTest. Registered tests (verified with `ctest -N`):
`errorHandlingTest`, `gslLinkTest`, `integrationSmokeTest`, `testTest`.

- `test/errorHandlingTest.cpp` covers `AppException` and the `errorMessageHandler`
  funnel (Critical throws a catchable `AppException`; Info/Warning/Debug do not).
- `test/gslLinkTest.cpp` proves `Microsoft.GSL::GSL` links (`gsl::not_null`).
- `test/integrationSmokeTest.cpp` proves Qt + Boost + ms-gsl link together and
  pins `BOOST_VERSION >= 109100` (i.e. >= 1.91.0).
- `test/testTest.cpp` is the baseline template test.

Exact commands (verified against the configured `build/` on this machine):

```bash
# One-time bootstrap of Conan + deps
bash conanLibrariesInstall.sh          # or: make conan

# Configure + build both targets (Release)
make build
# equivalently:
cmake . -G Ninja -B build -DCMAKE_TOOLCHAIN_FILE=conan/conan_toolchain.cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j4

# Run the test suite headless
make test
# equivalently:
cd build && QT_QPA_PLATFORM=offscreen ctest -C Release -VV

# List tests without running (verified: 4 tests)
cd build && ctest -N

# Preset-driven alternative
cmake --preset ninja-release && cmake --build --preset release && ctest --preset release
```

Lint/format checks:

```bash
make format   # find src test -name '*.cpp' -o -name '*.h' | xargs clang-format -i
make tidy     # find src -name '*.cpp' | xargs clang-tidy -p build --config-file=.clang-tidy
```

Conspicuously untested within this domain: there is **no test** asserting the
two-target invariant (that exe and `_LIB` are built from identical sources), no
test that any sanitizer/coverage option actually configures, no verification that
`Boost::filesystem` (as opposed to header-only Boost) links, and no CMake-level
config-time assertions. Sanitizer/coverage builds are only reachable by hand
(`-Dqt6-template_ENABLE_ASAN=ON`, etc.); CI does not exercise them.

## Extension points

- **Add a Qt module**: append to `QT_COMPONENTS` in `cmake/Modules.cmake:7`. The
  `find_package` (`CMakeLists.txt:39-45`) and the `project_link_dependencies` helper
  (`cmake/Modules.cmake:15-17`) pick it up. Adding `Quick` additionally enables the
  QML resource path.
- **Add a Boost component**: append to `BOOST_COMPONENTS`
  (`cmake/Modules.cmake:5`); resolved by the Boost `find_package` loop (`:30-32`) and
  linked by `project_link_dependencies` (`cmake/Modules.cmake:18-20`).
- **Add a Conan-provided CONFIG package**: add to `[requires]` in
  `conan/conanfile.txt`, re-run `make conan`, then add its `find_package` target
  name to `MODULES` (`cmake/Modules.cmake:3`) so the generic loops handle it.
  Header-only single-target libs (like GSL) currently need a bespoke
  `target_link_libraries` line inside `project_link_dependencies`
  (`cmake/Modules.cmake:21`) instead.
- **Add a system (module-mode) package**: add to `SYS_MODULES`
  (`cmake/Modules.cmake:1`); found via `find_package(... REQUIRED)` (`:19-21`).
- **Add a build toggle / sanitizer**: follow the `option()` +
  `add_compile_options`/`add_link_options` pattern in
  `cmake/StandardSettings.cmake:39-55`. Keep the `qt6-template_` prefix and place
  it before `add_subdirectory(test)` so it reaches tests.
- **Add resources**: extend `RESOURCES` in `cmake/Resources.cmake:11-13`
  (`TEST_RESOURCES` is derived automatically with the `../` prefix).
- **Add a source file**: drop it under `src/` - the `GLOB_RECURSE` in
  `Sources.cmake` picks it up on the next configure (re-run `cmake` since globs are
  not auto-tracked).
- **Add a Makefile shortcut**: add a `target: ## description` line; `make help`
  auto-discovers it via the `grep`/`awk` in `Makefile:12-14`. Note CLAUDE.md
  describes the 12-target set as "frozen".
- **Switch to a library-only build**: configure with
  `-Dqt6-template_BUILD_EXECUTABLE=OFF`; the single `qt_add_library(qt6-template)`
  branch (`:114-116`) and the test-lib fallback (`test/CMakeLists.txt:69-73`) take
  over.

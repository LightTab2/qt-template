# CI/CD (GitHub Actions) - analysis

## Purpose

This subsystem is the repo's automated build/test/release plumbing, expressed entirely as GitHub Actions
workflows under `.github/`. It solves four problems for a cross-platform Qt6/CMake/Conan template:
(1) verify every pull request builds and passes the Qt test suite on Linux in both Release and Debug (and
on macOS/Windows in Release); (2) auto-version `main` by pushing an incrementing tag on each merge;
(3) build per-OS binary artifacts and publish them as draft pre-releases attached to that tag; and
(4) build and publish the Doxygen documentation to a `docs` branch. A weekly Dependabot config keeps the
Action versions and the single pip dependency (`conan`) current.

## Owned paths

Disjoint globs this domain owns:

- `.github/workflows/**` - all eight workflow YAML files (`ubuntu.yml`, `ubuntu-debug.yml`, `macos.yml`,
  `windows.yml`, `doxygen.yml`, `autotag.yml`, `actionlint.yml`, `lint.yml`).
- `.github/dependabot.yml` - Dependabot update schedule.

Co-located under `.github/` but NOT owned by CI (repo-meta / AI-docs, functionally separate domains):

- `.github/copilot-instructions.md`, `.github/instructions/addLibrary.instructions.md` - Copilot/AI guidance
  (AI-docs domain). Flagged: stale relative to the current build system (see Tech debt).
- `.github/ISSUE_TEMPLATE/bug_report.md`, `.github/ISSUE_TEMPLATE/feature_request.md` - GitHub issue forms
  (repo-meta). The plan explicitly froze these as off-limits for the CI feature
  (`plan/04-ci/feature.md`: "Do NOT touch: `.github/ISSUE_TEMPLATE/**` ... `.github/copilot-instructions.md`").

Paths this domain READS/DEPENDS ON but does NOT own (owned by other domains - do not edit from here):

- `scripts/run_doxygen.sh` (docs domain 02) - invoked verbatim by `doxygen.yml`.
- `conan/conanfile.txt` (deps/build domain 01) - hashed into the Conan cache key and consumed by `conan install`.
- `requirements.txt` (repo root; deps domain) - contains the single line `conan`; `pip install -r requirements.txt`
  is how CI acquires the Conan client.
- `CMakeLists.txt`, `cmake/**`, `test/**` (build/test domain) - the build/test targets CI drives.
- `Makefile` (domain 03) - the local mirror of the CI commands (see drift table).
- `icon/*.png`, `config.desktop` (packaging assets) - consumed by the Linux AppImage step.

## Key files & symbols

CI has no "symbols" in the code sense; the load-bearing units are workflows, their jobs, and their steps.

| File | Central unit(s) | One line |
|------|-----------------|----------|
| `.github/workflows/ubuntu.yml` | job `build_and_deploy` | PR build/test on `ubuntu-latest`, Release; on Autotag success builds an AppImage and drafts a pre-release. |
| `.github/workflows/ubuntu-debug.yml` | job `build_and_test_debug` | PR-only Debug build + offscreen ctest; least-privilege `contents: read`, never deploys. |
| `.github/workflows/macos.yml` | job `build_and_deploy` | Same shape as ubuntu, packages `build/install/*` into a `.tar.gz` draft pre-release. |
| `.github/workflows/windows.yml` | job `build_and_deploy` | Same shape, PowerShell steps, packages `install` into a `.zip` via 7z. |
| `.github/workflows/doxygen.yml` | job `create_docs` | On push to main, runs `scripts/run_doxygen.sh` and publishes `docs/html` to the `docs` branch. |
| `.github/workflows/autotag.yml` | job `tag` | On push to main, computes the next `X.Y.Z` tag and pushes it (bootstrap `1.0.0`). |
| `.github/workflows/actionlint.yml` | job `actionlint` | On PRs touching `.github/workflows/**`, downloads pinned actionlint 1.7.7 and lints all workflow YAML (`-shellcheck=` disabled). |
| `.github/workflows/lint.yml` | job `clang-format` | On `pull_request: main`, runs `clang-format --dry-run --Werror` over `src` and `test`. |
| `.github/dependabot.yml` | `updates[]` | Weekly `github-actions` and `pip` dependency PRs. |

## Architecture & responsibilities

Two independent event fabrics converge on `main`:

1. Push-to-main fabric: `autotag.yml` and `doxygen.yml` both fire on `push: main`. Autotag creates a version
   tag; Doxygen (independently, in parallel) rebuilds and republishes docs.
2. Release fabric: the three build workflows fire on `workflow_run` completion of `Autotag`. When Autotag
   succeeds, each OS build workflow re-runs in "deploy mode", derives the tag Autotag just created, builds a
   per-OS artifact, and uploads it as a draft pre-release.
3. PR fabric: the same three build workflows plus `ubuntu-debug.yml` fire on `pull_request: main`. In this
   mode the deploy/packaging steps are gated off (`if: github.event_name == 'workflow_run'`), so a PR only
   builds and tests.

```
   git push -> main
      |                                   \
      v                                    v
 [autotag.yml]  push tag X.Y.Z        [doxygen.yml]  run_doxygen.sh -> publish docs/html
      | (workflow_run: completed=success)      -> branch `docs` (peaceiris, force_orphan)
      v
 workflow_run trigger
      |----> [ubuntu.yml  deploy]  -> linuxdeploy AppImage  -> draft pre-release @ tag
      |----> [macos.yml   deploy]  -> tar.gz build/install  -> draft pre-release @ tag
      |----> [windows.yml deploy]  -> 7z    build/install   -> draft pre-release @ tag

   open PR -> main
      |----> [ubuntu.yml  PR check]   build+test (deploy steps skipped)
      |----> [macos.yml   PR check]   build+test
      |----> [windows.yml PR check]   build+test
      |----> [ubuntu-debug.yml]       Debug build+test (contents: read)
```

Every workflow carries the FC04.1 "hardening block": a `concurrency` group
`${{ github.workflow }}-${{ github.ref }}` plus a least-privilege `permissions:` scope. The three
`cancel-in-progress` policies are deliberately distinct (see Data structures).

## Data structures & models

There are no runtime data structures; the "schemas" are YAML config shapes. The load-bearing ones:

FC04.1 hardening block, per-workflow (the three cancel-in-progress values are the crux):

| Workflow | `cancel-in-progress` | `permissions` | Rationale |
|----------|----------------------|---------------|-----------|
| `ubuntu.yml`, `macos.yml`, `windows.yml` | `${{ github.event_name == 'pull_request' }}` | `contents: write` | PR runs supersede stale PR runs; the `workflow_run` deploy path must NEVER be cancelled mid-release-upload. |
| `ubuntu-debug.yml` | `true` | `contents: read` | Supersedable PR check; publishes nothing. |
| `doxygen.yml` | `true` | `contents: write` | Supersedable docs build; pushes the `docs` branch. |
| `autotag.yml` | `false` | `contents: write` | Serialize tag pushes; a cancelled mid-flight run would drop a version tag (`autotag.yml:10` comment). |

Autotag version model (`autotag.yml:24-40`): tags are plain `X.Y.Z` strings. Next tag is computed by
incrementing only the last dot-segment of the most recent tag:

```bash
LAST_TAGGED_COMMIT=$(git rev-list --tags --max-count=1)
if [ -z "$LAST_TAGGED_COMMIT" ]; then
  TAG="1.0.0"                                  # bootstrap
else
  TAG=$(git describe --tags "$LAST_TAGGED_COMMIT")
  TAG=${TAG%.*}.$((${TAG##*.} + 1))            # 1.0.0 -> 1.0.1 -> 1.0.2 ...
fi
```

Only the patch (last) component ever advances; there is no path to bump minor or major automatically.

Conan cache key model (identical in all four build workflows, e.g. `ubuntu.yml:62-68`):

```yaml
path: ~/.conan2
key: conan2-${{ runner.os }}-${{ hashFiles('conan/conanfile.txt') }}
restore-keys: conan2-${{ runner.os }}-
```

Dependabot model (`dependabot.yml`): version 2; two ecosystems (`github-actions` and `pip`), both
`directory: "/"`, both `schedule.interval: "weekly"`. There is no `conan` ecosystem (Dependabot does not
support Conan), so C++ dependency bumps are manual.

Artifact naming model:

- Linux: `<repo-name>.AppImage` (from `steps.repoName.outputs.name`).
- macOS: `<repo-name>_macOS_<tag>.tar.gz`.
- Windows: `<repo-name>_Win_<tag>.zip`.

`steps.repoName.outputs.name` is `${GITHUB_REPOSITORY##*/}` on Unix (`ubuntu.yml:32-36`,
`macos.yml:32-36`) and the PowerShell `Split("/")[-1]` equivalent on Windows (`windows.yml:34-37`).

## Control & data flow

Primary path 1 - merge to main triggers a release:

1. A commit lands on `main`. Both `autotag.yml` (job `tag`) and `doxygen.yml` (job `create_docs`) start.
   Autotag first checks `if: !contains(head_commit.message, '[skip ci]'/'[ci skip]')` (`autotag.yml:17`).
2. `autotag.yml` "Create and push tag" step: if `git describe --exact-match HEAD` succeeds the commit is
   already tagged and it exits 0; otherwise it computes the next tag (model above) and `git push --tags`
   (`autotag.yml:24-40`).
3. Autotag completing with `conclusion == 'success'` fires the `workflow_run` trigger on `ubuntu.yml`,
   `macos.yml`, `windows.yml`. Each job's `if:` re-checks success and the skip-ci guard against
   `github.event.workflow_run.head_commit.message` (`ubuntu.yml:25-30`).
4. Each build workflow: Extract repo name -> `actions/checkout@v6` -> (deploy-only) `git fetch --tags origin`
   -> (deploy-only) derive `versionTag` via `git describe --tags $(git rev-list --tags --max-count=1)`
   (`ubuntu.yml:41-51`) -> `setup-python@v6` (pip cache) -> `pip install -r requirements.txt` (installs Conan)
   -> `actions/cache@v5` for `~/.conan2` -> `conan profile detect --force` + `conan install --build=missing conan/`
   -> `jurplel/install-qt-action@v4` (Qt `6.11.*`, aqt `==3.2.*`, cached) -> `cmake -Bbuild -DCMAKE_TOOLCHAIN_FILE=... -DCMAKE_BUILD_TYPE=Release`
   -> `cmake --build build --config Release --target install -j4` -> offscreen `ctest -C Release -VV`;
   `ubuntu.yml` additionally runs `QT_QPA_PLATFORM=offscreen timeout 15 ./build/qt6-template --self-test`
   after the build (`ubuntu.yml:92`, the R7 smoke gate).
5. Deploy-only packaging (gated `if: github.event_name == 'workflow_run'`):
   - Linux (`ubuntu.yml:94-115`): `apt-get install libxcb-cursor-dev`, download `linuxdeploy` +
     `linuxdeploy-plugin-qt` continuous AppImages, build `AppDir` from `./build/<name>` with the six
     `icon/icon_*.png` sizes and `config.desktop`, emit `<name>.AppImage`, then `softprops/action-gh-release@v3`
     uploads it as `draft: true, prerelease: true, tag_name: <tag>`.
   - macOS (`macos.yml:96-110`): `tar -czvf` over `build/install/*` then the same release action.
   - Windows (`windows.yml:97-112`): rename `install` -> `<name>`, `7z a -r` into a `.zip`, then release action.

Primary path 2 - docs publish: `doxygen.yml` checks out (`fetch-depth: 0`), `apt-get install graphviz`,
runs `bash scripts/run_doxygen.sh` (which pins Doxygen 1.17.0, fetches Qt tag files, renders the vendored
`doxygen-style-revamped` theme, copies webfonts), then `peaceiris/actions-gh-pages@v4` publishes
`./docs/html` to `publish_branch: docs` with `force_orphan: true` (`doxygen.yml:23-31`).

Primary path 3 - PR validation: a PR against `main` triggers all four build workflows in check-only mode
(deploy steps skipped by the `if:`), plus `ubuntu-debug.yml` which runs the same acquire-deps flow but
configures `-DCMAKE_BUILD_TYPE=Debug`, builds `--config Debug -j4`, and runs `ctest -C Debug -VV` offscreen
(`ubuntu-debug.yml:43-50`). The Debug job's skip guard reads the PR title, not a commit message
(`ubuntu-debug.yml:19-21`). Both `ubuntu.yml` and `ubuntu-debug.yml` also run the built exe with
`--self-test` under `QT_QPA_PLATFORM=offscreen timeout 15` after the build (`ubuntu.yml:92`,
`ubuntu-debug.yml:49`). Two more PR workflows fire: `lint.yml` (clang-format `--dry-run --Werror` over
`src`/`test`) and `actionlint.yml` (only when `.github/workflows/**` changes).

CI-to-local command mapping (drift flagged):

| CI step | CI command | Local equivalent | Drift |
|---------|-----------|------------------|-------|
| Acquire Conan | `pip install -r requirements.txt` | system `conan` or `./conanLibrariesInstall.sh` (venv) | Local can use a venv; CI installs into the runner's Python. |
| Conan install (Release) | `conan install --build=missing conan/` (Release only) | `make conan` = install Debug AND Release | `make conan` installs both configs; the Release CI job installs one. |
| Conan install (Debug) | `conan install conan/ --build=missing -s build_type=Debug` | `make conan` (Debug half) | Match. |
| Configure | `cmake -Bbuild -DCMAKE_TOOLCHAIN_FILE="conan/conan_toolchain.cmake" -DCMAKE_BUILD_TYPE=Release` (Debug job uses `=Debug`; `windows.yml` is multi-config and passes none; no `-G Ninja`) | `make configure` = `cmake . -G Ninja -B build -DCMAKE_TOOLCHAIN_FILE=... -DCMAKE_BUILD_TYPE=Release` | CI uses the platform default generator (Unix Makefiles / VS), local forces Ninja. Build type now matches ctest `-C`: single-config CI jobs pass an explicit `-DCMAKE_BUILD_TYPE`. |
| Build | `cmake --build build --config Release --target install -j4` | `make build` = `cmake --build build --config Release -j4` (default target) | CI Release builds the `install` target; `make build` does not install. |
| Test | `QT_QPA_PLATFORM=offscreen ctest -C Release -VV` (from `build/`) | `make test` = `cd build && QT_QPA_PLATFORM=offscreen ctest -C Release -VV` | Match. |
| Docs | `bash scripts/run_doxygen.sh` | `make docs` = `bash scripts/run_doxygen.sh` | Match. |

## Public API / contracts

What other domains and the repo rely on from CI:

- Trigger contract: build/test runs on `pull_request: main`; the release path runs on `workflow_run`
  completion of the `Autotag` workflow. Renaming the `Autotag` workflow (its `name:` key) breaks the
  `workflows: [Autotag]` reference in all three build workflows.
- Autotag contract: pushing to `main` (without `[skip ci]`/`[ci skip]`) creates and pushes an
  incrementing `X.Y.Z` tag; the first ever tag is `1.0.0`. Downstream release naming and the README release
  badge depend on this tag existing.
- Artifact contract: three named draft pre-release artifacts per tag - `<name>.AppImage`,
  `<name>_macOS_<tag>.tar.gz`, `<name>_Win_<tag>.zip` - each `draft: true, prerelease: true`.
- Docs contract: the `docs` branch is an orphan branch containing `docs/html` output; consumed by GitHub
  Pages if the repo is configured to serve Pages from the `docs` branch (that Pages setting is a repo-level
  config, NOT present in these files - there is no `actions/deploy-pages`/`configure-pages` in the repo).
- Build-command contract (consumed FROM domains 01/02): the exact `conan install` / `cmake` / `ctest`
  invocations, the `~/.conan2` cache keyed on `conan/conanfile.txt`, Qt `6.11.*`, and `bash scripts/run_doxygen.sh`.
- README badge contract (`README.md:1-5`): badges point at `workflows/macos.yml`, `windows.yml`,
  `ubuntu.yml`, `ubuntu-debug.yml` and the releases page; the workflow `name:` values ("macOS", "Windows",
  "Ubuntu", "Ubuntu Debug") back the badge label URLs.

## Invariants & assumptions

- Qt tests need a platform plugin or they hang: every ctest invocation sets `QT_QPA_PLATFORM=offscreen`
  (all four build workflows). Removing it hangs CI.
- The `Autotag` workflow `name:` must equal the string referenced in the build workflows'
  `workflow_run.workflows: [Autotag]`. They are coupled by name, not by file path.
- Autotag assumes tags are clean `X.Y.Z`. It increments the base tag found via
  `git rev-list --tags --max-count=1` + `git describe --tags`, which on an exactly-tagged commit yields the
  bare tag, so `${TAG%.*}.$((${TAG##*.}+1))` parses. A tag not matching `*.*.*` (or a `-N-gsha` describe
  suffix) would corrupt the next tag.
- The Conan cache key assumes `conan/conanfile.txt` fully captures dependency identity; changing pinned
  versions there rotates the cache (correct), but changes to the Conan profile do not.
- The macOS/Windows packaging assumes `--target install` populated `build/install` (macOS/Windows install
  prefix); Linux packaging instead assumes the built binary sits at `./build/<name>` (its install prefix is
  `$HOME/install`, so it bypasses the install tree). See Gotchas.
- The FC04.1 cancel-in-progress triple is an invariant enforced by the plan gate: `false` on autotag,
  `true` on debug/doxygen, `${{ github.event_name == 'pull_request' }}` on the three deploy workflows. The
  gate (`plan/04-ci/task-04-tests.md`) hard-fails on any deviation.

## Error handling & edge cases

- Skip-ci: `[skip ci]`/`[ci skip]` in the head commit message short-circuits `autotag.yml` (`:17`) and the
  build workflows' `workflow_run` gate (`ubuntu.yml:29-30`); for the Debug PR check the sentinel is looked
  for in the PR title instead (`ubuntu-debug.yml:20-21`) - an asymmetry (see Gotchas).
- Already-tagged commit: `autotag.yml` detects `git describe --exact-match HEAD` and exits 0 rather than
  creating a duplicate tag (`:26-28`).
- No prior tags: Autotag bootstraps `1.0.0`; the build workflows' `versionTag` step is deploy-only, so a
  first-ever push (Autotag creates `1.0.0`) yields the tag for the subsequent deploy runs.
- Release safety: `cancel-in-progress: false` (autotag) and the PR-only cancel expression (deploy
  workflows) exist specifically so an in-flight tag push or release upload is never cancelled.
- Doxygen offline/missing-tool paths are handled inside `scripts/run_doxygen.sh` (graphviz check, pinned
  binary download with primary+fallback URLs, Qt-tags refetch-if-missing), not in `doxygen.yml`.
- No explicit `timeout-minutes`, no `continue-on-error`, no retry on the build/test steps; a flaky Conan
  Center or aqt mirror fails the run outright (only `curl --retry 3` inside `run_doxygen.sh` retries).

## Concurrency / async / lifecycle

- Cross-workflow ordering is asynchronous via `workflow_run`: Autotag must finish (success) before the
  deploy builds start. There is a race window where the deploy build's checkout/`git fetch --tags` must see
  the tag Autotag just pushed; this works because deploy runs are triggered by Autotag completion.
- Per-workflow concurrency groups (`${{ github.workflow }}-${{ github.ref }}`) serialize same-ref runs.
  PR pushes cancel stale PR runs; the release path does not cancel (policy table above).
- `doxygen.yml` and `autotag.yml` both fire on the same push to `main` and run concurrently - independent,
  no ordering guarantee between docs and tagging.
- Lifecycle of a release: draft pre-release is created but not published; a human must publish it. Draft +
  prerelease is intentional (allows attaching files across the three OS runs to one tag).

## Performance

- Caching is the main performance lever: `~/.conan2` via `actions/cache@v5` (keyed on the conanfile hash,
  with a prefix `restore-keys` fallback), Qt via `install-qt-action` `cache: 'true'`, and pip via
  `setup-python` `cache: 'pip'`. Cold cache means a full Conan `--build=missing` (can rebuild Boost) plus a
  full Qt download.
- Builds use `-j4` fixed parallelism regardless of the runner's core count (all build workflows).
- The Doxygen build is offline after first run (binary + Qt tags cached in-tree by `run_doxygen.sh`); in CI
  the `.doxygen-bin/` and `doxygen/qt-tags/` caches are not persisted across runs (they are gitignored and
  not wired into `actions/cache`), so the CI docs job re-downloads the Doxygen binary and Qt tags every run.

## Gotchas & footguns

- Build type is now explicit on single-config jobs. `ubuntu.yml:81` and `macos.yml:81` configure with
  `-DCMAKE_BUILD_TYPE=Release`, `ubuntu-debug.yml:43` with `=Debug`, each matching the job's `ctest -C`
  config. The dead top-level `env: CMAKE_BUILD_TYPE` block has been removed from every workflow.
  `windows.yml` keeps its multi-config generator and controls config at build time (`--config Release`),
  so it carries no `-DCMAKE_BUILD_TYPE`.
- Generator drift: CI uses each platform's default generator (Unix Makefiles on Linux/mac, Visual Studio on
  Windows); `make configure` forces `-G Ninja`. A Ninja-only CMake construct would pass locally and fail in
  CI (or vice-versa). Multi-config generators (VS) make `--config` meaningful; single-config (Makefiles)
  ignore it and rely on the toolchain/`CMAKE_BUILD_TYPE`.
- Skip-ci sentinel location differs: commit message for autotag + deploy builds, but PR title for
  `ubuntu-debug.yml` (`:20-21`). Putting `[skip ci]` in a commit will not skip the Debug PR check; you must
  put it in the PR title.
- `git rev-list --tags --max-count=1` picks the most recent tagged commit by history order, not by semver.
  If tags are ever created out of order, both Autotag's increment base and the deploy `versionTag` pick the
  "wrong" tag. Fine for linear `main`, fragile otherwise.
- Only the patch segment auto-increments (`1.0.0 -> 1.0.1 -> ...`). There is no automated minor/major bump;
  you must push a manual tag to jump minor/major, then autotag continues from there.
- Linux packaging uses the raw build output `./build/<name>` (`ubuntu.yml:105`), NOT an install tree,
  because the Linux install prefix is `$HOME/install` (`CMakeLists.txt:293`), whereas macOS/Windows package
  `build/install`. This asymmetry is intentional but non-obvious; the executable landing at `build/<name>`
  depends on the single-config default output dir (no explicit `RUNTIME_OUTPUT_DIRECTORY` is set for the
  executable target in `CMakeLists.txt`).
- A committed workflow lints the CI. `.github/workflows/actionlint.yml` runs a pinned actionlint
  (1.7.7, `-shellcheck=` disabled per FC03.1) on every PR touching `.github/workflows/**`, and
  `.github/workflows/lint.yml` runs `clang-format --dry-run --Werror` over `src` and `test` on every PR.
  (`.gitignore:374-376` still ignores the `/actionlint` binary the download form drops in the worktree root.)
- `ubuntu.yml:73` runs `conan install --build=missing conan/` (flags before the path); `macos.yml`/`windows.yml`
  use `conan install conan/ --build=missing`. Same effect, cosmetic inconsistency.
- Deprecated dead end (git history): the OLD `doxygen.yml` (commit `93c3164`) used the
  `doxygen-awesome-css` git submodule + `DenverCoder1/doxygen-github-pages-action` and a hand-rolled
  font-copy commit onto the `docs` branch. It was fully replaced (commit `30fb61d`, "modernize CI to PVN
  architecture") by the `bash scripts/run_doxygen.sh` + `peaceiris/actions-gh-pages` pipeline. The plan gate
  asserts `! grep -q "doxygen-awesome" .github/workflows/doxygen.yml`. Do not reintroduce
  doxygen-awesome-css or the submodule approach.
- Dependabot has no Conan ecosystem (unsupported); C++ dependency bumps in `conan/conanfile.txt` are manual.

## Tech debt & smells

- `.github/copilot-instructions.md:9-17` documents setup via `./conanLibrariesInstall.sh` and a Ninja
  configure, but omits the newer `Makefile` entrypoint and the `ms-gsl` dependency; it is drifting from the
  current build system (the plan explicitly left it untouched).
- `.github/instructions/addLibrary.instructions.md` is a two-line stub (`applyTo: '**'` + one generic
  sentence) with no actual guidance - dead weight.
- Fixed `-j4` across all build workflows ignores runner core count (`ubuntu.yml:87` et al.).
- CI docs job re-downloads Doxygen 1.17.0 + Qt tags every run because `.doxygen-bin/` and `doxygen/qt-tags/`
  are not wired into `actions/cache` (`doxygen.yml` has no cache step). Wasted bandwidth per push to main.
- Three near-duplicate build workflows (`ubuntu.yml`, `macos.yml`, `windows.yml`) differ only in packaging
  and shell; there is no reusable/composite workflow, so a build-step change must be made in three places
  (plus the fourth, `ubuntu-debug.yml`).
- No `timeout-minutes` on any job; a hung download can run to the 6h GitHub default.
